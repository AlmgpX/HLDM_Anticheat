# Детектор HLDM

## Что он действительно ловит

`hldm_detector.amxx` анализирует только серверные данные `usercmd` и положение игроков. Он не сканирует процессы, память или файлы клиента.

Используются четыре сигнала:

1. **Snap fire**: большой поворот камеры за короткий `usercmd`, после которого выстрел направлен в живого игрока.
2. **Instant reaction**: выстрел попадает в игрока почти сразу после того, как тот впервые стал видимым.
3. **Rapid target switch**: два выстрела по разным игрокам с быстрым крупным переводом прицела.
4. **Invalid angles**: невозможные углы пользовательской команды.

Одиночный быстрый флик не включает ловушку. По умолчанию нужны:

```cfg
hldm_ac_auto_threshold "100.0"
hldm_ac_minimum_categories "2"
hldm_ac_minimum_events "5"
```

То есть автоматическая реакция требует серии событий и как минимум двух разных типов сигнала. Человек иногда делает безумный флик. Человек редко делает пять машинно одинаковых чудес подряд, хотя человечество настойчиво пытается опровергнуть даже это.

## Режимы

```text
amx_ac_mode 0   выключить
amx_ac_mode 1   только наблюдать и писать лог
amx_ac_mode 2   автоматически вызывать amx_trap
```

Режим по умолчанию: `2`.

## Команды

```text
amx_ac_status
amx_ac_status #17
amx_ac_reset #17
amx_ac_reset @all
amx_ac_mode 1
amx_ac_testtrap #17
```

`amx_ac_testtrap` нужен для проверки связи двух плагинов. Он не имитирует чит, а просто посылает выбранному клиенту обычную команду ловушки.

## Логи

События записываются в:

```text
valve/addons/amxmodx/logs/hldm_anticheat_events.log
```

Каждая строка содержит:

- тип сигнала;
- имя, SteamID/ValveID и IP;
- `userid`;
- добавленные очки и измеренное значение;
- итоговый score;
- ping и loss.

Отключение подробного лога:

```cfg
hldm_ac_log_events "0"
```

## Настройка чувствительности

Начинать следует с стандартных значений. Если сильные честные игроки регулярно достигают `60`, сначала увеличь `hldm_ac_auto_threshold` до `130`, а не превращай сервер в гадалку с кувалдой.

Для периода калибровки:

```cfg
hldm_ac_mode "1"
```

После нескольких матчей изучи `hldm_anticheat_events.log`, затем верни режим `2`.

## Ограничения

Детектор не доказывает наличие конкретной программы и не ловит все виды wallhack. Его задача: автоматически выделять повторяющуюся машинную стрельбу и передавать устойчиво подозрительного клиента в серверную ловушку.

Однопиксельные и нестандартные модели обрабатываются отдельно плагином `hldm_trap.amxx`: модель заменяется на штатную, а клиент может быть помечен сразу.

## Steam и LAN-клиенты

Для обычного Steam-клиента ловушка сохраняется по SteamID через nVault.

У клиента с `STEAM_ID_LAN` или `VALVE_ID_LAN` автоматическая ловушка работает в текущем подключении, но постоянная запись намеренно не создаётся. Хранить наказание по одному IP было бы удобным способом однажды наказать соседа, нового владельца адреса и роутер. Поэтому такой цирк выключен.
