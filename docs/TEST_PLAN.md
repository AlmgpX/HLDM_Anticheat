# План проверки HLDM Anticheat 1.0

## 1. Автоматические проверки

```text
python tools/check_contract.py
```

CI дополнительно:

- проверяет синтаксис всех PowerShell-скриптов;
- компилирует `hldm_trap.sma` и `hldm_detector.sma` AMX Mod X 1.10.0.5479;
- требует ненулевые `.amxx`;
- собирает установочный ZIP;
- блокирует клиентские команды, кик и бан.

## 2. Проверка установки

После запуска созданного launcher:

```text
meta list
amxx version
amxx modules
amxx plugins
```

Ожидается:

```text
Metamod running
AMX Mod X running
Fakemeta running
Ham Sandwich running
nVault running
hldm_trap.amxx running
hldm_detector.amxx running
```

В логах AMXX не должно быть `bad load`, `native error` или `invalid player`.

## 3. Интеграция двух плагинов

1. Подключить тестового клиента B.
2. Выполнить `status`.
3. Выполнить `amx_ac_testtrap #USERID_B`.
4. Проверить B через `amx_trap_list`.
5. Выполнить `amx_untrap #USERID_B`.
6. Убедиться, что B вернулся к обычному поведению.

## 4. Обычный матч

1. Запустить HLDM с двумя обычными клиентами A и B.
2. Оставить `hldm_ac_mode 1`, ловушку никому не назначать.
3. Сравнить урон оружия, прыжки, стрейф и primary/secondary fire.
4. Играть минимум 10 минут.
5. Убедиться, что детектор только пишет score, а ввод и урон не меняются.
6. Проверить отсутствие runtime errors и резкого роста CPU.

## 5. Ручная цель

1. Выполнить `amx_trap #USERID_B`.
2. Проверить, что A не изменился.
3. Проверить уменьшение исходящего урона B.
4. Проверить увеличение входящего урона B.
5. Проверить редкие пропуски прыжка, primary fire, secondary fire и инверсию стрейфа.
6. Дождаться `RECOVERY` и проверить временное исчезновение эффектов.
7. Выполнить `amx_untrap #USERID_B`.

## 6. Детектор в observe-only

1. Установить `amx_ac_mode 1`.
2. Выполнить `amx_ac_reset @all`.
3. Провести матч с сильным честным игроком.
4. Периодически выполнять `amx_ac_status #USERID`.
5. Проверить строки в `hldm_anticheat_events.log`.
6. Убедиться, что одиночный быстрый флик не приводит к автоматической ловушке.

## 7. Синтетическая проверка сигналов

Без запуска реального чита можно воспроизвести только часть поведения:

- быстрые крупные флики с выстрелом по видимой цели должны повышать `snap`;
- быстрый перевод между двумя стоящими рядом игроками должен повышать `switch`;
- многократный выстрел сразу после выхода цели из-за стены должен повышать `reaction`;
- обычное движение без выстрелов не должно повышать score.

После серии выполнить:

```text
amx_ac_status #USERID
```

Проверить рост соответствующих счётчиков, а не только общего score.

## 8. Автоматический режим

1. Установить `amx_ac_mode 2`.
2. На тестовом стенде временно снизить:

```cfg
hldm_ac_auto_threshold "30.0"
hldm_ac_minimum_categories "1"
hldm_ac_minimum_events "1"
```

3. Воспроизвести snap-fire.
4. Проверить автоматическое появление клиента в `amx_trap_list`.
5. Вернуть штатные значения `100 / 2 / 5` до публичного запуска.

## 9. Персистентность

1. Добавить Steam-клиента через `amx_trap_id STEAM_...`.
2. Переподключить клиента.
3. Проверить восстановление ловушки.
4. Выполнить `amx_untrap_id STEAM_...` в онлайне и офлайне.
5. Убедиться, что администратор с immunity не восстанавливается как цель.
6. Убедиться, что LAN-ID не создаёт постоянную запись.

## 10. Model guard

1. Установить клиенту `model cdc` или другое нестандартное имя.
2. Проверить замену на `gordon` через `user <userid>`.
3. При auto-trap=1 проверить причину `custom-model` в `amx_trap_list`.
4. Проверить, что десять штатных моделей не заменяются.
5. Проверить защиту администратора и бота от автоматической ловушки.

## 11. Аварийные выключатели

```text
amx_trap_stop
amx_ac_mode 0
```

Проверить немедленное прекращение:

- изменения урона и ввода;
- HUD цели;
- model guard;
- сбора новых detector-сигналов.

Затем:

```text
amx_trap_start
amx_ac_mode 2
```

Список постоянных целей должен сохраниться.

## 12. Повторное использование слота

1. Пометить клиента B.
2. Отключить B.
3. Подключить нового клиента C, который получит тот же entity slot.
4. Убедиться, что C не наследовал `g_trapped`, score, углы, счётчики или last target.

## 13. Критерий допуска

- CI зелёный;
- оба Pawn-плагина компилируются без ошибок и предупреждений;
- PowerShell parse чистый;
- `amxx plugins` показывает оба `running`;
- integration test проходит;
- обычный клиент не затронут ловушкой;
- observe-only не применяет наказание;
- auto-mode применяет ловушку только после выполнения всех порогов;
- в логах нет runtime errors.
