# План проверки

## 1. Статический контракт

```text
python tools/check_contract.py
```

Проверяется:

- наличие исходника, конфига, документации, CI и установщиков;
- отсутствие клиентских команд, кика и бана;
- наличие всех admin-команд и safety-cvar;
- соответствие cvar исходника и конфига в обе стороны;
- отсутствие старого ошибочного пути `configs/hldm_trap.cfg`.

## 2. Компиляция

GitHub Actions компилирует `.sma` официальным AMX Mod X 1.10 build 5479 и публикует:

- `hldm_trap.amxx`;
- готовый ZIP с деревом `addons/amxmodx/...`.

Любая ошибка Pawn должна блокировать PR.

## 3. Smoke test обычного матча

1. Запустить HLDM с двумя обычными клиентами A и B.
2. Не включать ловушку.
3. Сравнить урон каждого оружия, прыжки, стрейф и primary/secondary fire.
4. Убедиться, что эффекты не проявились минимум за 10 минут.
5. Проверить нагрузку `stats` и отсутствие ошибок AMXX в логах.

## 4. Ручная цель

1. Выполнить `status` и `amx_trap #USERID` только для B.
2. Проверить, что A не изменился.
3. Проверить уменьшение исходящего урона B.
4. Проверить увеличение входящего урона B.
5. Проверить редкие пропуски прыжка, primary fire, secondary fire и инверсию стрейфа.
6. Дождаться `RECOVERY` и убедиться, что эффекты временно исчезают.
7. Выполнить `amx_untrap #USERID` и проверить возврат к ванильному поведению.

## 5. Персистентность

1. Добавить B через `amx_trap_id STEAM_...`.
2. Переподключить B.
3. Проверить автоматическое восстановление ловушки.
4. Выполнить `amx_untrap_id STEAM_...` в онлайне и офлайне.
5. Убедиться, что администратор с immunity не восстанавливается как цель.

## 6. Аварийный выключатель

1. При активной цели выполнить `amx_trap_stop`.
2. Проверить немедленное прекращение урона, usercmd-эффектов, HUD и model guard.
3. Выполнить `amx_trap_start`.
4. Убедиться, что список целей сохранился.

## 7. Model guard

1. Установить клиенту `model cdc` или другое нестандартное имя.
2. Проверить замену на `gordon` через `user <userid>`.
3. При auto-trap=1 проверить причину `custom-model` в `amx_trap_list`.
4. Проверить, что все десять штатных моделей не заменяются.
5. Проверить, что администратор и бот защищены от автоматической ловушки.

## 8. Критерий допуска в main

- CI зелёный;
- `amxx plugins` показывает `running`;
- в логах нет runtime errors;
- двухклиентный smoke test пройден;
- обычный клиент не затронут.
